# Chat 的可信知识库

> source id: `knowledge.chat_trusted_knowledge_base`

`zhiqiang.chat` 的知识库应该是人工维护的可信源，而不是让线上对话自动改写的动态记忆。

Chat 的职责是检索、引用和表达知识库里的内容；知识是否正确、是否代表我的真实理解，仍然由我在开发和内容维护时负责。

## 维护边界

> source id: `knowledge.chat_trusted_knowledge_base.boundary`

正式知识库只放我确认过的理解、判断和项目事实。对话过程中即使出现用户纠错，也不应该直接修改正式知识。

更稳的方式是把用户问题、未命中问题和可疑点记录下来，后续由我人工整理进知识库。这样可以避免用户误导、模型误判和公开问答污染可信内容。

## 对话引用方式

> source id: `knowledge.chat_trusted_knowledge_base.chat_usage`

Chat 回答问题时，可以优先引用 `status: published` 的知识内容。草稿、低置信度或未确认内容不应该进入公开回答。

如果知识库没有覆盖某个具体事实，Chat 应该说明资料未覆盖，再给出通用判断或建议，而不是补出看似合理但没有依据的内容。

## 后续迭代方向

> source id: `knowledge.chat_trusted_knowledge_base.iteration`

这个知识库可以先用 MDX 文件维护，构建时转成可检索语料。后续如果内容规模变大，再补搜索、embedding、知识图谱或后台编辑。

真正有价值的迭代不是自动改知识，而是持续发现缺口：哪些问题经常被问到但没有命中资料，哪些知识过久未更新，哪些内容需要拆成更清晰的知识单元。
