# 第 03 章：怎样高效阅读这个仓库

阅读日期：2026-09-14。书中版本基线：核心分析 v0.66.0，作者自述对照 v0.82.1；本笔记未独立验证源码或发行版本。

## 设计问题、机制与取舍

阅读从 agent 类型、Models、循环与 Agent 壳开始，再看 ai 公共出口、会话、提示装配、edit 和扩展接口。具体 UI、provider 和生成目录应按问题进入，而非逐文件扫描。

一条有效追踪链是：工具结果进入消息，循环追加历史，provider 转为请求格式。AgentMessage 能扩展业务消息，送模型时再收敛；provider 泛型守住协议边界，通用 Context 无须一直按厂商分叉。Extension 是执行代码，Skill 是文档资源。构建生成目录虽不宜逐行阅读，仍须理解其生成与更新方式。

## 工程应用检查（整理者推导）

为当前知识库选一条真实问题作为读码任务：“新增草稿为什么没有出现在访客回答里？”从工具返回类型开始，依次定位写入函数、frontmatter 解析、公开筛选、检索切块和引用展示。每到一处记录输入、输出和过滤条件，最后用一份临时草稿验证，而不是凭入口文件猜测行为。

对大型仓库可建立很短的阅读记录：问题、关键类型、调用者、被调用者、实际观察。遇到自动生成文件先找生成脚本和输入来源；遇到一个泛型先问它约束的是协议、数据，还是宿主业务上下文。这样可以决定哪里必须深入、哪里只需知道契约。

书中路径只作为定位线索。执行修改之前，用当前版本搜索确认文件和导出仍存在，并区分示意代码与可执行代码。把“找到了同名函数”提升为“追通了一条请求与结果链”，才算完成读码验收；这是整理者建议。
